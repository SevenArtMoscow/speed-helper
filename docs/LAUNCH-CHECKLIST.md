# Чек-лист запуска в продакшен

Что сделано в коде, а что нужно сделать вам (то, что требует ваших аккаунтов, документов и решений).

## ✅ Уже сделано
- Вход только через подпись Telegram, JWT на 7 дней, права проверяются на сервере в каждой функции; поддельные данные и токены отклоняются.
- Защита от повторов и гонок (двойной отклик, принятие сверх мест), проверка всех полей (даты, время, суммы, длины), понятные сообщения об ошибках.
- Лимиты на частоту запросов (приложение + nginx), закрытый порт приложения, заголовки безопасности (строгий CSP, HSTS, nosniff), исходники и `.env` не раздаются.
- Предстартовое укрепление (миграция `020`, `deploy/setup.sh`): фото — только картинки до ~75 КБ; ссылки и @username в именах и названиях смен запрещены (они уходят в уведомления бота); лимиты на тяжёлые выборки, избранное и журнал событий; смены заблокированного скрываются; тайм-ауты запросов к БД; CSP пускает только библиотеку карты нужной версии; права админа — строго по `ADMIN_TG_IDS`; сервис изолирован (код только для чтения, своя /tmp), роль БД без CREATEROLE, бэкапы закрыты от чтения, лимиты и тайм-ауты nginx, защита бота от флуда.
- Подтверждение 18+ и принятие соглашения при первом входе (проверяет сервер), отдельное согласие на дополнительные данные с отзывом, журнал согласий, документы №1–3 по постоянным адресам, **удаление аккаунта** кнопкой (право на удаление данных).
- Старт без каталога: анкету исполнителя видит только подрядчик смены с действующим откликом, телефон в анкету не входит, поля «медкнижка» нет.
- Бэкапы БД каждую ночь с проверкой, восстановление одной командой, автоматическая очистка старых служебных данных.
- Мониторинг: автоперезапуск, оповещения админам в Telegram (сбои, диск, сертификат), fail2ban против подбора пароля SSH, автообновления безопасности, своп, настройка PostgreSQL.
- Чат с подрядчиком сразу после отклика, архив чатов при отказе от смены, служба поддержки в приложении (ответы реплаем в Telegram), подтверждение номера кодом (SMS/Telegram Gateway) или через бота.
- Автотесты (≈640 проверок) и CI на GitHub.

## ⚠️ Нужно сделать вам до запуска (по важности)
1. **Документы:** реквизиты оператора теперь внутри текстов `https://speedhelper.ru/legal/terms.html`, `/legal/privacy.html`, `/legal/additional-data.html`. Покажите их **юристу** и направьте уведомления в Роскомнадзор, о которых говорит Политика (обработка персональных данных и трансграничная передача, п. 7.5).
2. **Перевыпустить токен бота** (он засветился в переписке): @BotFather → `/revoke` → новый токен → заменить на сервере (команда в `docs/OPERATIONS.md`).
3. **Сменить root-пароль сервера** (он тоже засветился на скриншоте) и перейти на вход по SSH-ключу: ключ в `/root/.ssh/authorized_keys`, затем `SSH_KEYS_ONLY=1 bash setup.sh` (см. `docs/OPERATIONS.md`).
4. **Ограничить ключ DaData своим доменом:** личный кабинет dadata.ru → API-ключ → разрешённые сайты → `speedhelper.ru`. Ключ виден в коде страницы, без ограничения его могут израсходовать чужие сайты (лимит 10 000 запросов в день — и подсказки адресов перестанут работать).
5. **Firewall в Timeweb** (Сервер → Сеть → Firewall): группа правил «входящие — только 22, 80, 443». Второй слой к ufw на самом сервере. Перед крупным обновлением — **снапшот** (Сервер → Бэкапы → Создать снапшот).
6. ~~Ключ DaData~~ — подключён (аккаунт SevenArtQ, бесплатный тариф 10 000 запросов/день; ключ в `js/config.js`).
7. **Мини-приложение в @BotFather:** Bot Settings → Configure Mini App → URL `https://speedhelper.ru`; задайте аватар, описание, `/setcommands` выставляется ботом сам.
8. **Каждый админ один раз нажимает Start у бота** — иначе оповещения о сбоях не дойдут.
   **Поддержка:** вписать Telegram ID Серёги в `SUPPORT_TG_IDS` и нажать ему Start у бота; для кодов подтверждения — выбрать провайдера (`SMS_PROVIDER`, см. `docs/OPERATIONS.md`).
9. **Копия бэкапов вне сервера:** `BACKUP_REMOTE` (rsync по ssh) либо ручное скачивание раз в неделю. Один сервер = одна точка отказа.
10. **Поддержка:** `SUPPORT_URL=https://t.me/ваш_аккаунт` — появится кнопка «Написать в поддержку».
11. **Проверка на живых людях** (закрытый тест 5–10 человек, обе роли, свои телефоны): отклик → принятие → чат → завершение → оценка.

## 💡 Рекомендуется после запуска
- Включить бэкапы сервера в Timeweb (Бэкапы → расписание) — второй независимый слой.
- Подключить внешний аптайм-монитор (например UptimeRobot, бесплатно) на `https://speedhelper.ru/api/health`.
- Отдельный тестовый бот и тестовый сервер (staging) для проверки обновлений до выкладки на боевой.
- Платный тариф DaData/карт понадобится только при росте нагрузки.
