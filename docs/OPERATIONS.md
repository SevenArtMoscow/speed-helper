# SPEED HELPER — эксплуатация

Прод: один VPS (Timeweb Cloud, Ubuntu). Приложение — `/opt/speedhelper`, сервис `speedhelper` (Node.js), PostgreSQL, nginx + HTTPS (Let's Encrypt). Консоль сервера: Timeweb → Облачные серверы → SPEED HELPER PROD NSK → «Консоль».

## Обновление версии
Код берётся из ветки `main` на GitHub. Быстрое обновление (без перезаписи настроек nginx), с бэкапом БД:
```bash
speedhelper-backup && G="git -c safe.directory=/opt/speedhelper -C /opt/speedhelper"; $G fetch -q origin main && $G reset -q --hard origin/main && (cd /opt/speedhelper/server && npm ci --omit=dev --ignore-scripts --silent) && systemctl restart speedhelper && sleep 4 && curl -s https://speedhelper.ru/api/health
```
Миграции базы применяются автоматически при старте. Полное обновление системных настроек (nginx, fail2ban, PostgreSQL, мониторинг, изоляция сервиса): `bash setup.sh` (скачивается как в README; данные и `.env` не трогает). **После обновлений, меняющих `deploy/setup.sh`, запускайте именно его**, а не быструю команду — иначе новые настройки сервера не применятся.

Код в `/opt/speedhelper` принадлежит root и только читается сервисом (взломав приложение, нельзя подменить его код). Сервис пишет лишь в `/var/lib/speedhelper` (там `welcome-file-id` — запомненная анимация бота).

## Откат
```bash
G="git -c safe.directory=/opt/speedhelper -C /opt/speedhelper"
$G log --oneline -10                       # найти предыдущую версию
$G reset --hard <хеш> && systemctl restart speedhelper
```
Миграции только добавляют (новые таблицы и поля), поэтому откат кода назад безопасен. Если сломана сама база — восстановление из копии (ниже).

## Резервные копии
- Автоматически каждую ночь в 03:30: `/var/backups/speedhelper/db-ГГГГ-ММ-ДД.dump`, хранятся 14 дней; копия проверяется на читаемость. Журнал: `/var/log/speedhelper-backup.log`. В копиях персональные данные — папка и файлы доступны только root.
- Вручную: `speedhelper-backup`.
- **Копия на другой машине (рекомендуется):** впишите в `/opt/speedhelper/server/.env` строку `BACKUP_REMOTE=пользователь@хост:/путь` (нужен доступ по ssh-ключу с сервера) — каждая ночная копия будет отправляться туда. Либо периодически скачивайте файлы из `/var/backups/speedhelper`.
- Восстановление: `speedhelper-restore /var/backups/speedhelper/db-ГГГГ-ММ-ДД.dump` (перед этим делается страховочная копия; потребуется ввести слово ВОССТАНОВИТЬ). Проверяйте восстановление на тестовом сервере хотя бы раз.

## Мониторинг и оповещения
Админы из `ADMIN_TG_IDS` получают сообщения в Telegram (нужно один раз нажать Start у бота):
- 🔄 сервер запущен/перезапущен, 🛑 сервер упал (перезапускается сам);
- 🛑 сервис не отвечает — `speedhelper-health` (раз в минуту) перезапускает его; ✅ когда восстановился;
- ⚠️ диск заполнен на 85%+, сертификат HTTPS заканчивается (≤14 дней), нужна перезагрузка после обновлений.

Полезные команды:
```bash
systemctl status speedhelper            # состояние
journalctl -u speedhelper -n 100        # последние записи журнала
journalctl -u speedhelper -f            # следить за журналом
tail -50 /var/log/speedhelper-health.log
fail2ban-client status sshd             # заблокированные за подбор пароля
certbot renew --dry-run                 # проверка автопродления сертификата
```
Статистика и жалобы — в самом приложении: Админ-панель (кнопка на стартовом экране и в профиле у админов).

## Секреты и их замена
Все секреты — в `/opt/speedhelper/server/.env` (права 600, в git не попадают).
- **Токен бота:** @BotFather → `/revoke` → выбрать бота → новый токен. Заменить: `sed -i 's|^TG_BOT_TOKEN=.*|TG_BOT_TOKEN=НОВЫЙ|' /opt/speedhelper/server/.env && systemctl restart speedhelper`.
- **JWT_SECRET:** замена выкинет всех пользователей из сессии (они войдут заново автоматически): `sed -i "s|^JWT_SECRET=.*|JWT_SECRET=$(openssl rand -hex 32)|" /opt/speedhelper/server/.env && systemctl restart speedhelper`.
- **Пароль root сервера:** Timeweb → сервер → Доступ, либо `passwd`. Лучше перейти на вход по SSH-ключу: добавьте свой публичный ключ в `/root/.ssh/authorized_keys`, проверьте вход по ключу в отдельном окне и запустите `SSH_KEYS_ONLY=1 bash setup.sh` — вход по паролю отключится (если ключа нет, установщик пароль не отключит, чтобы не потерять доступ). Консоль Timeweb работает всегда, даже если SSH недоступен.
- **Права админа** есть ровно у тех, кто сейчас в `ADMIN_TG_IDS`: убрали человека из списка и перезапустили сервис — при следующем входе в приложение права пропадут.
- Токен, пароль или ключ, попавшие в переписку/скриншот, считайте скомпрометированными и заменяйте.

## Настройки (`server/.env`)
| Переменная | Что делает |
|---|---|
| `TG_BOT_TOKEN`, `ADMIN_TG_IDS`, `APP_URL`, `JWT_SECRET`, `DATABASE_URL` | основные (создаются установщиком) |
| `OPERATOR_NAME`, `OPERATOR_CONTACT` | оператор данных и контакт — подставляются в политику конфиденциальности и соглашение (**обязательно заполнить до запуска**) |
| `SUPPORT_URL` | ссылка «Написать в поддержку» в профиле (например `https://t.me/ваш_аккаунт`); пусто — кнопки нет |
| `PRIZES_TEXT` | текст про призы на экране «Рейтинг исполнителей» (например: «1 место — 5 000 ₽, 2 место — 3 000 ₽»); пусто — показывается общая фраза |
| `BACKUP_REMOTE` | куда отправлять копии БД (см. выше) |
| `TG_BOT_TOKEN_OLD` | токен прежнего бота на время переезда на новый (см. «Переезд на новый бот»); пусто — переезда нет |
| `SUPPORT_TG_IDS` | Telegram ID сотрудников поддержки через запятую (см. «Служба поддержки»); пусто — вместо чата поддержки ссылка `SUPPORT_URL` |
| `SMS_PROVIDER` | подтверждение номера кодом: `smsru` (нужен `SMSRU_API_ID`, по желанию `SMSRU_FROM` — согласованное имя отправителя) или `tg_gateway` (нужен `TG_GATEWAY_TOKEN`, код приходит в Telegram на этот номер); пусто — номер подтверждается только кнопкой «Поделиться номером» в боте |
| `PG_POOL_MAX`, `TZ_DB` | размер пула соединений (10) и часовой пояс БД (Europe/Moscow) |
| `PG_STATEMENT_TIMEOUT_MS` | сколько максимум может идти один запрос к БД (15000 мс); дольше — запрос прерывается, пользователь видит «Сервер перегружен», в журнале `rpc timeout` |

После изменения: `systemctl restart speedhelper`.

## Нагрузка и лимиты
- На запросы действуют лимиты: вход — 30 в минуту на пользователя Telegram и 300 в минуту с одного адреса (у мобильных операторов за одним IP бывают сотни людей), действия — 400 в минуту на пользователя, плюс отдельные лимиты (сообщения 40/мин и 600/час, создание смен 15/час, жалобы 10/час, избранное 300/час, тяжёлые выборки — лента 120/мин, рейтинг 20/мин и т. д.) и лимиты nginx на адрес (50 запросов/с, 100 соединений). Превышение — сообщение «Слишком много действий подряд». Боту один человек может написать не больше 20 сообщений в минуту — остальные бот молча пропускает.
- Один запрос к БД идёт не дольше 15 с, при нехватке соединений запрос ждёт не больше 10 с и получает «Сервер перегружен» (а не копится в памяти). Если такие ответы появляются под нагрузкой — `journalctl -u speedhelper | grep -E "rpc timeout|pg connect failed"`.
- Сервер: 4 CPU / 8 ГБ. Одного процесса Node.js с запасом хватает на тысячи активных пользователей; узкое место при росте — выборка смен и опрос обновлений раз в 4 секунды. При росте нагрузки: поднять тариф в Timeweb, затем вынести БД на отдельный сервис.
- Старые события, ключи идемпотентности и отправленные уведомления очищаются автоматически (раз в 6 часов).

## Переезд на новый бот
Что бот настраивает сам при запуске с новым токеном: команды (/start, /help, /privacy), описание и короткое описание, кнопку меню «Открыть» с мини-приложением; приветственную анимацию (`assets/welcome.mp4`) он загрузит при первом /start.

Только вручную в @BotFather (у нового бота):
- аватар: `/setuserpic` → `icons/icon-512.png`;
- картинка до нажатия Start: Edit Bot → Edit Description Picture → `assets/welcome.gif`;
- главное мини-приложение (кнопка «Открыть» в профиле бота): Bot Settings → Configure Mini App → Enable → `https://speedhelper.ru`.

На сервере (новый код уже выложен через `bash setup.sh`). Прежний токен сохраняется как `TG_BOT_TOKEN_OLD`, новый вписывается на его место:
```bash
cd /opt/speedhelper/server && grep -q '^TG_BOT_TOKEN_OLD=' .env || sed -n 's/^TG_BOT_TOKEN=/TG_BOT_TOKEN_OLD=/p' .env >> .env
nano .env    # в строке TG_BOT_TOKEN= вставить новый токен из @BotFather
systemctl restart speedhelper && journalctl -u speedhelper -n 30
```
Пока задан `TG_BOT_TOKEN_OLD`:
- приложение, открытое из прежнего бота, по-прежнему пускает (тот же аккаунт — он привязан к Telegram, а не к боту);
- прежний бот на любое сообщение отвечает «SPEED HELPER переехал в @новый_бот» с кнопками «Перейти» и «Открыть»;
- уведомления тем, кто ещё не нажал Start в новом боте, приходят через прежний с припиской «нажмите Start в @новый_бот».

Админам (`ADMIN_TG_IDS`) и поддержке (`SUPPORT_TG_IDS`) нужно нажать Start в новом боте — иначе оповещения о сбоях и обращения до них не дойдут.
Когда все переехали (обычно через 2–4 недели), удалите строку `TG_BOT_TOKEN_OLD` из `.env` и `systemctl restart speedhelper`.
Токен не пересылайте в чатах и не кладите в git: он только в `/opt/speedhelper/server/.env`.

## Служба поддержки
- В приложении: Профиль → «Написать в поддержку» — у пользователя открывается чат с поддержкой.
- Обращение бот пересылает в Telegram всем из `SUPPORT_TG_IDS` (каждый должен один раз нажать Start у бота). **Ответить — реплаем (Reply) на это сообщение бота**: ответ появится у пользователя в приложении и придёт ему сообщением от бота.
- Ещё можно отвечать в приложении: «Обращения в поддержку» (на стартовом экране и в профиле у сотрудников поддержки) или кнопка «Открыть обращение» под сообщением бота. Обращения, ждущие ответа, отмечены точкой.
- Свой Telegram ID человек видит в админ-панели (вкладка «Пользователи», строка «tg …»), если хоть раз открывал приложение. Добавить сотрудника: вписать ID в `SUPPORT_TG_IDS`, `systemctl restart speedhelper`.
- Лимит: не больше 30 сообщений в поддержку в час от одного человека.

## Подтверждение номера
- Кодом (если задан `SMS_PROVIDER`): человек вводит номер → получает 6-значный код (SMS через sms.ru или в Telegram через Telegram Gateway) → вводит код. Код живёт 10 минут, 5 попыток; новый код — не чаще раза в минуту и не больше 5 в сутки на человека и на номер; общий потолок — 300 кодов в час (защита от «накрутки» платных SMS). В базе хранится только хеш кода.
- Без кода: кнопка «Подтвердить через Telegram» → в чате с ботом «Поделиться номером» (бесплатно, работает всегда).
- Один номер — один аккаунт. Подтверждённый номер виден в профиле владельцу; у исполнителя в карточке телефон помечается «✓ подтверждён», если совпадает с подтверждённым.
- sms.ru: зарегистрироваться, пополнить баланс, взять API-ключ (api_id) в кабинете → `SMS_PROVIDER=smsru`, `SMSRU_API_ID=...`. Telegram Gateway: gateway.telegram.org → токен → `SMS_PROVIDER=tg_gateway`, `TG_GATEWAY_TOKEN=...`. Затем `systemctl restart speedhelper`. Сбои отправки — в журнале: `journalctl -u speedhelper | grep "phone code send failed"`.

## Удаление данных пользователя (152-ФЗ)
Пользователь удаляет аккаунт сам: Профиль → «Удалить аккаунт» — профиль, избранное, уведомления стираются, активные смены и отклики отменяются, сообщения обезличиваются. По письменному запросу: удалить так же через админ-панель нельзя, но можно заблокировать аккаунт; полное удаление строки — SQL `psql -d speedhelper` (делайте бэкап перед правкой).

`cd server && npm test` — запускает настоящий сервер на встроенной PostgreSQL и проверяет весь API (≈510 проверок: права доступа, неверные данные, лимиты, удаление аккаунта, заголовки безопасности). Выполняется и автоматически в GitHub Actions при каждом push.

## Тестовая нагрузка («кипящая» работа)
Симулятор `server/tools/simulator.mjs` заводит выдуманных людей (по 200 исполнителей и подрядчиков; `tg_id` отрицательный, пометка `users.is_fake`) и ведёт их «рабочий день» через настоящий API: публикуют смены, откликаются, принимают/отклоняют, пишут в чаты, отмечают явку, завершают смены, ставят оценки. Плюс ~80 «открытых приложений» опрашивают сервер раз в 4 секунды, как настоящие клиенты. Участники команды (настоящие аккаунты) «вклиниваются»: на их отклики к тестовым сменам подрядчики отвечают, на личные сообщения отвечают, тестовые исполнители откликаются на их смены.

```bash
# запуск на 6 часов (в фоне, переживает закрытие консоли)
systemd-run --unit=speedhelper-sim --collect node /opt/speedhelper/server/tools/simulator.mjs --users 200 --rate 2
journalctl -u speedhelper-sim -f -n 20        # показатели каждые 10 секунд: запросов/с, задержка p50/p95, ошибки, открытых смен
node /opt/speedhelper/server/tools/simulator.mjs --status    # сколько тестовых записей
systemctl stop speedhelper-sim                                # остановить (данные остаются)
node /opt/speedhelper/server/tools/simulator.mjs --clean      # удалить ВСЁ тестовое (смены, отклики, чаты, отзывы, пользователей)
```
Параметры: `--rate` действий в секунду (по умолчанию 2), `--online` число «открытых приложений» (80), `--hours` автостоп (6), `--seed` смен на старте (150), `--cap` потолок открытых тестовых смен (600), `--age` через сколько секунд смену можно завершать (120).

Что изолировано: тестовым пользователям бот ничего не отправляет; в админке цифры «Показатели» считаются без тестовых (они отдельной строкой), в списках настоящие идут первыми, тестовые с пометкой «тест»; в рейтинге исполнителей тестовые видны только администраторам. Телефоны тестовых подрядчиков вида `+7 (000) 000-00-01`. Нагрузку смотрите в журнале симулятора, в Мониторинге Timeweb (процессор, память) и в `journalctl -u speedhelper`. Симулятор ходит на приложение напрямую (`127.0.0.1`, мимо nginx и HTTPS), поэтому проверяет приложение и базу, а не сеть.

## Связь сервера с Telegram
DNS на VPS периодически сбоил (бот терял связь: «fetch failed» в `journalctl -u speedhelper`), поэтому адрес Telegram закреплён в `/etc/hosts` на сервере:
`149.154.167.220 api.telegram.org`. Копия исходного файла — `/etc/hosts.bak-speedhelper`.
**Если бот вдруг перестал отвечать надолго** — Telegram мог сменить адрес: уберите эту строку (`sed -i '/api.telegram.org/d' /etc/hosts`) и перезапустите `systemctl restart speedhelper`.
Проверка связи: `for i in $(seq 1 10); do curl -s -m 5 -o /dev/null -w "%{http_code} " https://api.telegram.org/bot0/getMe; done` (должно быть почти везде 404 — это нормально для проверочного токена).
Остаточные редкие обрывы (~10%) бот перекрывает повторами; при заметном ухудшении сети рассмотрите перенос сервера в Москву.
